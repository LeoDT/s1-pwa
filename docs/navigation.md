# 导航与页面框架（App 式）

> 结论：**放弃浏览器式前进/后退历史，改用固定的层级路径 + 手势返回。**
> 本文件替代 overview.md 中 D16/D17 关于导航与返回的描述。

## 1. 固定层级

```
板块列表（每个板块一个固定路径 /f/<fid>，内部无限滚动）
浏览历史（/history，与板块列表占用同一个列表区域）
   └─ 帖子详情（/t/<tid>[/<page>][#pid<pid>]，从历史进入则为 /history/t/…）
         返回 → 正常浏览回原列表（保留滚动位置）；深链或整页刷新后回该帖所属板块，从历史进入则回历史列表
```

- 没有"全局后退按钮"：顶栏不提供返回箭头。
- 返回只有两个入口：**详情页横向滑动**、系统返回键/手势（Android 硬件键、iOS 边缘手势）。
- 板块切换、板块/历史之间的切换不是"历史"，是**替换当前列表**。
- 帖子内的翻页、引用跳楼、跨帖跳转一律 **replace**，不堆历史；所以系统返回永远只回列表。

## 2. 路由行为表

| 动作 | 路由 | 历史操作 |
|---|---|---|
| 打开帖子 | `/t/<tid>` | push（小屏唯一一次入栈）/ replace（大屏） |
| 帖子翻页 | `/t/<tid>/<page>` | replace |
| 引用跳楼 / 跨帖跳转 | `/t/<tid>/<page>#pid…` | replace |
| 返回列表（滑动/硬件键） | `/f/<原列表 fid>`；深链初始化后为所属板块 | 小屏有列表栈 → pop；否则 replace |
| 列表滚动到底 | 路由不变（追加下一页） | 无 |
| 切换板块 | `/f/<fid>` | replace |
| 打开浏览历史 | `/history` | 浏览页内 replace（切换列表区域）；其它页 push |
| 从历史打开帖子 | `/history/t/<tid>[/<page>]` | push（小屏）/ replace（大屏） |
| 历史里翻页 / 引用跳楼 | `/history/t/<tid>/<page>` | replace |
| 从历史返回列表 | `/history` | 有列表栈 → pop；否则 replace |
| 打开设置（含板块管理） | 弹层，路由不变 | — |

深链直达或整页刷新 `/t/...` 时没有列表栈，先根据帖子数据初始化所属板块列表；尚未确认所属板块时不猜测返回目标。正常浏览中返回原列表，大屏使用 replace，小屏有列表栈时返回上一层。

## 3. 顶栏（常驻 / 仅小屏详情页收起）

顶栏中间**永远是站点名 `Stage1st`**，不显示板块名或帖子标题——标题属于内容，见 §5。

| 场景 | 顶栏 |
|---|---|
| 列表页（小屏 / 大屏） | **常驻**，作为布局中的一行（不遮挡内容） |
| 详情页（大屏） | **常驻** |
| 详情页（小屏 < 1024） | **浮层**：不占布局高度，向下滚动收起、向上或回到顶部（`scrollTop < 8`）展开 |
| 非浏览页（诊断） | 常驻 |

小屏详情页为浮层时，滚动容器顶部预留 `header-h + safe-area-top`，所以停在顶部时标题可见。
顶栏右侧是「浏览历史 + 设置」两个按钮；历史列表激活时历史按钮转主题色并带 `aria-current="page"`。大屏下顶栏内容与内容框同宽（`--frame-w: 1320px` = 420 + 900）。

## 4. 列表页

- **无限滚动**：首屏拉第 1 页，滚动到底部前 600px 自动追加下一页（`IntersectionObserver`），末尾保留一个可点的「加载更多（n / N 页）」作为键盘/失败兜底。
- **去重**：置顶帖会在每一页重复出现，按 `tid` 去重，保留首次出现的位置。
- **页码与 URL 无关**：追加页不改路由；URL 里只有 `fid`。
- **显式刷新**：请求期间保留已有列表与滚动位置；新第一页成功返回后原子替换全部旧页并回到顶部。失败保留列表并提示错误；刷新期间暂停追加页。
- **大屏没有下拉手势**：板块条右侧固定一个刷新按钮（等价于下拉刷新 = 回第 1 页，列表回到顶部）；详情页底栏右侧同样有一个刷新按钮（重取当前页）。
- 小屏仍是下拉刷新。板块列表在本次会话中保留缓存，不因窗口聚焦、重新挂载或网络恢复而自动刷新；首次无缓存加载和滚动追加页不受影响。
- 浏览路由共用常驻布局，打开帖子、翻页和跨帖跳转不卸载原列表，也不自动请求或切换到目标帖所属板块；保留已加载页及滚动位置。小屏仅隐藏列表，并暂停隐藏列表的触底加载和下拉刷新。
- 板块条贴在**列表底部**：小屏为屏幕底部固定条，大屏为左栏（420px）底部固定条，同一个组件、同一位置语义。
- 板块按钮使用可增长、不压缩的 flex 布局：空间充足时填满剩余宽度，放不下时横向滚动。小屏隐藏滚动条，大屏露出 4px 细滚动条且滚轮可横滚。
- 板块条只有切换，没有"管理"入口（管理在设置抽屉里）。

### 4.1 浏览历史列表

- 历史按钮切换的是**列表区域**，不是独立页面：小屏占满、大屏占左栏，与板块列表共用同一套布局。
- 行样式与板块列表共用 `ListRow`：左侧徽章显示上次读到第几楼，标题两行，次级信息为「板块 · 时间」；从历史打开的帖子行显示激活态。
- 底部板块条保留；点任一板块 tab 即切回该板块列表（列表跟着板块/历史走，不依赖浏览器后退）。
- 列表头部显示「浏览历史」与「清空」；行右侧垃圾桶删除单条。
- 下拉刷新（小屏）与板块条右侧刷新按钮（大屏）重新拉取最近阅读，期间保留旧列表；缓存按 UID 区分，过期刷新响应不提交。
- 点击条目直接回到上次楼层（`/history/t/<tid>[/<page>][#pid]`）。

## 5. 详情页

- 常驻浏览容器统一持有当前帖/页的查询结果，正文与首次初始化所属板块使用同一份数据。列表来源只保存在当前布局生命周期内，URL 不额外携带 `fid`，也不持久化最后访问板块。
- 整页刷新或深链进入时，先加载帖子，确认可靠 `fid` 后再初始化所属板块列表；期间左侧使用延迟加载态，不提前请求默认板块 4。有缓存时直接恢复；请求失败可重试，无法解析所属板块时显示未知状态。
- 正常浏览中的翻页和跨帖跳转保留现有列表，即使目标帖属于其他板块，也不会重建列表或改变返回目标；只有显式切换板块/历史才替换列表来源。详情页刷新按钮只重取当前帖子页，不重建列表。从历史进入仍保留历史列表。
- 顶部是**内容内的标题块**：帖子标题（h1，17/600 两行内）+ 元信息（板块 · 页码 · 本页楼层数），随后才是楼层。标题随内容滚动，不占顶栏。
- 页码条**统一在内容区底部**（小屏与大屏一致，都贴所在栏的底部）：`« ‹ 3 / 15 › »`，首/末页按钮在边界禁用；详情页仍然按钮翻页（不做无限滚动）。底栏在正常 flex 流中占位，刷新按钮不覆盖分页，极窄宽度下分页可换行。
- 横向滑动返回：位移 > 70px 且纵向位移 < 50px，左右方向都接受（页面内没有横向内容，避免误伤）。**默认关闭**（`edgeSwipe: false`，避免与 iOS 原生边缘手势叠加），设置 → 阅读内可开启。
- 返回时恢复列表的滚动位置（已追加的页仍在 query 缓存里）。
- 从浏览历史进入的详情页，滑动返回/翻页/引用跳转都停留在历史列表旁。

所有瞬时 loading 提示（骨架、列表加载更多、刷新旋转和表单等待文案）延迟 200ms 显示，快速完成不显示；实际 busy/disabled 立即生效。

## 6. 设置入口

- 顶栏齿轮 → 设置抽屉。
- 抽屉内包含：**账号（未登录时可就地展开 S1 登录表单，不跳页）**、常用板块管理（就地编辑，不跳页）、正文字号/省流量/横向滑动返回、访问令牌、图片缓存、关于。
- 登录不再有独立页面（旧 `/login` 已删除）：登录表单内嵌在设置的账号区块，登录成功后表单收起、抽屉不关；除了顶栏齿轮，浏览历史页的未登录引导按钮也会直接拉起这个抽屉。
- 板块管理不再有独立路由（旧 `/boards` 已删除）：排序、移除、从板块树添加、手动填 fid 都在抽屉里完成；板块树只在展开「添加板块」时才请求。
